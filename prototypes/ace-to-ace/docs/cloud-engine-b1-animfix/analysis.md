# B1 動畫破綻：來源與修正取捨

基準 `996329258379383f6ed1d8bdb4ea992589be6c14`。本輪不生成新美術，不改 CloudField、正式遊戲、R2 素材或 Unreal。

## 原 B1 的問題

1. **錨點固定不等於物體固定。** Vertex shader 以 `normalize(eye-pCenter)` 重算 right/up，所以飛過或繞行時，整張圖會轉向觀察點。只在同一位置轉鏡頭，通常不會改片朝向；極頂視還會使用 viewMatrix 的 fallback。上一輪「轉開再轉回像素相同」只證明可重現，無法證明表面屬於固定三維物體。
2. **輪廓跟視角一起重建。** 仰角同時改變片高（`aSize.y → aSize.z`）、side/top/base 的 RGB 與 alpha。四張原創圖沒有共同三維形體的逐點對應，混合會讓塔狀輪廓、雲洞與雲底變形。浮雕深度也沿 eye ray 偏移，是視角相關的深度近似。
3. **整片按中心距離淡出。** `smoothstep(100,650,length(eye-pCenter))` 與近表面 15–110 m fade 會降低整張片的覆蓋率；它不代表眼前那個局部位置的真實密度。獨立的 3×3 CPU 霧網格無法保證在相同位置、相同輪廓接手，所以容易產生圖片融化。
4. **次要因素。** 18 張 detail 片在 4.5–7.5 km 淡出，會影響遠景層次，但不是近距穿幫的主因。B1 用 MSAA alpha-to-coverage 與 depth write，並非一般透明物件排序；4-sample 覆蓋率量化、相交片及視角相關浮雕深度仍可能像排序錯誤般改變遮蔽。

## 選擇的最小方案

| 方法 | 動畫上的風險 | 本輪決定 |
|---|---|---|
| 固定交叉片／法線片簇 | 消除追隨相機，但仍可能露交線、薄片與內部排序 | 不將既有四張互不對應的圖直接交叉 |
| 固定雲殼＋材質 | 剪影與視差穩定；進入封閉表面時仍需解決內外表面交接 | 保留為後續可比較方向，本輪不重做上一輪球殼／alpha 拼貼 |
| 固定三維密度＋世界材質 | 無片翻轉或表面交接；需要限制積分與貼圖成本，輪廓也較柔 | 採用有界 32 點積分作空間修正實驗 |

[NVIDIA GPU Gems 第 39 章](https://developer.nvidia.com/gpugems/gpugems/part-vi-beyond-triangles/chapter-39-volume-rendering-techniques)說明密度體的重建、梯度、沿視線累積及取樣率對品質的影響。本輪借用這些基本原理，沒有實作該章的完整光照／散射系統。[Three.js Data3DTexture](https://threejs.org/docs/pages/Data3DTexture.html)提供現有 WebGL2 所需的三維貼圖。這些來源不構成 iPhone 效能保證。

### 三個距離區域

- **遠景**：R2 天空背景保持原樣。可飛入雲區的遠端使用同一有限世界密度體的粗採樣，不額外放置會轉向相機的大圖。
- **中景／邊界**：從視線與雲區 AABB 的進入點起，前 240 m 有 8 點，接續 1200 m 有 12 點；其餘遠端 12 點，共最多 32 點。三區是數值精度分配，不是三張會互換的幾何 LOD。
- **近景／雲內**：眼睛在雲區內時，積分直接從眼睛前方開始，同樣的密度與世界筆觸仍存在。沒有整片中心距離 fade，也沒有另一層 fog 接手。實際遮蔽由 `1-exp(-0.012*rho*ds)` 累積到 opaque scene depth。

96×32×80 的 RGBA8 cache 儲存 B0 density 與世界梯度，三線性重建。seed／參數改變時建立一次；風只平移 cache 的世界位置。B0 函數與診斷 T500 完全保留，cache 是顯示近似。

筆觸在**每個世界採樣點**讀既有 RGB atlas，再累積顏色。固定三向投影不依眼睛方向或 top/side/base angle 換圖；密度梯度只用於世界日光與法線診斷，沒有改剪影。一般透明片數為零，一個深度感知合成 pass；沒有排序片群、TAA 或 96-step B1 pass。

## 實驗中淘汰的問題

第一版為省貼圖查詢，只在整條視線的加權中心取一次筆觸，近景出現拉伸／旋渦。第二版逐點採樣仍用密度梯度切不同投影素材，雲內梯度沒有穩定表面意義，出現條紋與高反差圖案。本輪改為固定、各向平均的單一材質場，降低筆觸反差，取消圖像家族切換。這解決了新引入的材質拉伸方向，代價是插畫細節下降。

初版採樣迴圈還使用隱含導數的 atlas 查詢。[GLSL ES 3.00 規格 §8.8](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf)說明這類導數在非一致控制流內沒有定義。因此最終版以 `textureLod` 明確指定 density cache 的 level 0，筆觸 mip 依距離與像素足跡連續選取。這沒有換剪影或移動幾何；它修正查詢定義，**沒有解決所有 GPU 成本**。

## 誠實的限制

此方案優先消除 billboard、視角形變與淡出交接，**沒有保留原 B1 的精細插畫剪影**。B0 的橢球群形體與平滑密度會讓外形較圓、較軟；近景有時偏均勻霧色。32 點與約 63×39×63 m 的積雲格距不能保留細雲絲，切線視角可能有取樣呼吸、明暗改變與輕微 banding。世界材質固定不等於足夠精細，也不代表動畫已達電影品質。

下一步應在固定三維位置上改善少量形狀／albedo 細節與採樣誤差，並在 iPhone Safari 測成本；不應再以互不對應的幾張圖隨視角換剪影。此輪仍留在 Cloud Lab。
