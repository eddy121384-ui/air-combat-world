# 虛擬搖桿回中與王牌飛行學院改善

日期：2026-10-23。基準為開始前查證的 PR #59 `feat/ace-flight-academy-v1` @ `49a007d9c19058cd1c39c6c5e5cc73649c01f0cf`；獨立 worktree／分支 `feat/ace-academy-controls-and-coaching`。本輪實作與測試，未修改飛行物理、武器平衡、AI、自由對戰規則、進度儲存格式或 Unreal。

## 搖桿修正

- `touchend`／`touchcancel` 清除該搖桿手指的 X/Y、位移、視覺旋鈕及所有權；下一次在新接觸點建立中立原點。其他手指放開不影響搖桿。
- **Expert 回中的是指令**：roll／pitch 都回零，沿用現有滾轉速率阻尼及自然飛行動態；沒有自動改平、姿態鎖定或新穩定器。Assisted 沿用既有協調轉彎／回中改平控制器。Arcade／Tactical 同規則。
- 油門位置與 AB 切換保留，BRK／GUN 等按住控制以手指所有權維持；同一按鈕有兩根手指時，放開一根不會誤放開另一根。
- 暫停／失焦／頁面隱藏／pagehide 清除暫時輸入與待發射指令，保留刻意鎖定的動力設定；重開沿用原本 72% 油門、AB 關閉的新架次規則。處理油門 lost-pointer-capture。
- 手指仍按住操縱時，瀏覽器不一定產生第二根手指的 click；暫停鈕因此直接處理 touchstart，抑制相容 click，避免必須先放開全部手指才能暫停。
- 死區 0.06、Expo 0.35/0.65、62px 半徑、靈敏度與 PlayerController 控制律不變。原本要求放開仍持續滾轉的 Node／Chromium 測試已改為新契約，沒有維持錯誤行為遷就測試。

實際 CDP 觸控將飛機滾至約 60° 後放開，經原始 `Match.step(1/60)` 推進 1.5 秒：Arcade／Expert 約 **62.5°**、Tactical／Expert 約 **62.1°**，滾轉速率收斂；兩種 Assisted 都逐漸回到接近水平。測試允許 <10° 的合理過渡，沒有要求姿態瞬間凍結；另檢查中立俯仰後姿態仍自然演化。手指事件是真實 Chromium CDP 事件；固定步長用來排除軟體 GPU 幀率對放手角度的干擾，不是 iPhone 手感測試。

## 最重要的五個設計問題

1. **L08 原口訣和實際瞄準器相反。** HUD 橘圈是 `gunLead()` 的世界提前點，應把機頭 W 對準它；「把圈疊到目標身上」會讓玩家追錯東西，而且原本直到失敗才解釋。現在練習中就比較機頭對本體／提前點的誤差，對症糾正。
2. **教官與任務不同步。** 長開場排在急迫指令之前；階段結束仍保留舊指令，字幕顯示與佇列停留時間也不同。現在情境在簡報、空中先說當下任務；最多 28 字短句，優先按完整句／子句斷開，共用停留時間，危險回饋可打斷，換階段／重試清掉過期字幕。
3. **部分教學契約與事實不一致。** L01／03「穩住」原可累積零碎秒數；L02 宣稱高度 <200m 卻沒判定；L05 結算固定宣稱用了 2300m；L07／09 失敗時可能仍稱控制滿 12 秒／三枚全躲掉。現在條件、實測值與稱讚一致；也修正「只滾不會轉」「AB 是唯一能量來源」等過度斷言。
4. **有數字，卻缺少玩家能在操作中觀察的對照。** L04 的高速基準直到結算才好比較；L05 的 E 是抽象大數字。現在即時顯示基準／本圈轉率，以及「高度＋動能高度＝能量高度」，用動作、證據、下一步三行提示代替讀不完的長目標。
5. **決策演示與任務收束不足。** L07 沒有清楚的追擊參考點、重要 overshoot 回饋路徑未覆蓋；L09 容易變成背時間；L10 只有一般過關感。現在有 LEAD／PURE／LAG 視覺參考、實際接近率修正、距離／接近時間判讀，以及實際評等與帶回耐久的 KITE 授證。

## 十堂課的獨立審查與實作

| 課 | 主要學習障礙 | 本輪改善與驗證重點 |
|---|---|---|
| L01 | 回中與姿態容易混淆；零碎平飛也能累積通過 | 分清 Expert 需反向滾轉改平／Assisted 放手改平；FPM 指引依高度誤差先爬升／下降、接近目標才改平；平飛與改平需連續穩住。 |
| L02 | 「滾轉才會轉」容易被記成口訣；宣稱的高度精度未考核 | 說清升力分量與維持高度；橫向回中後仍須拉桿；最後航向題顯示 14 秒／±4°／實際高度偏差，落實 200m 限制。 |
| L03 | 容易誤學成油門唯一決定速度／只有 AB 能恢復能量 | 即時顯示油門、MIL／AB、速度；看趨勢再修正；六秒連續定速，保留三種動力控制的獨立性。 |
| L04 | 把大 G 等同最快轉彎；缺少即時對照 | 保留同樣滿桿的高速／corner 對照；顯示實測 °/s 與高速基準、完成後顯示提升比例；MIL 一圈仍考守住結束速度。 |
| L05 | 能量高度不直覺；固定掉高數字與「驗證守恆」誤導 | 顯示兩個餘額、實際高度變化；明確扣除保留 400km/h 的動能及 300m 預算。引擎／阻力仍改變總額，未宣稱封閉系統守恆。 |
| L06 | 突發情境時仍可能在播上一段；「沒有升力」說法過頭 | 低速轉彎先提示減速至 420、進入後再提示守住 300；危險情境優先新指令。指出可用升力不足，不宣稱升力為零；維持失速近似與真實攻角失速的區分。 |
| L07 | 三種追擊缺乏可見參考；Pure 不一定造成 overshoot，原測試沒覆蓋三次穿越 | 增加未來／目前／過去位置的色彩參考點；根據實際距離與接近率提示，而非只按類型判錯。新增三次穿越的幾何判定測試，報穿越前的正接近率。 |
| L08 | 錯誤提前量口訣；只在失敗後才教 | W 對橘圈，練習中發現瞄本體 >0.6s 即修正；命中時給具體回饋。新增四模式瞄本體錯誤學員，維持 12 發／45 秒。 |
| L09 | 固定射擊容易背倒數；失敗結算可能反向稱讚 | 即時顯示距離、目前相對速度推算的接近時間；不是預測攔截保證。保留已校準完整關卡，另外改距離／間隔驗證飛彈段技巧可轉移；結果按實際發射／命中數呈現。 |
| L10 | 完成像另一張成績單，重試目標不夠具體 | KITE 發出開始指令與資格確認、ACE QUALIFIED 徽記、實際耐久／評等，以及下一個 S 目標。既有進度鍵與任意選課／自由對戰不變。 |

Pure pursuit 不是一律錯，Lag 也不是降低接近率的保證；速度、位置、轉彎圈仍重要。L07 的 ±2 秒標記只是教學參考點，不是完整 BFM 解算器。L09 的 0.5km 窗口是**本遊戲飛彈模型**，不能當成真實防禦教範。

## 代表性的前後對照

| 原行為／對白 | 改善後 |
|---|---|
| 放手仍保留最後滾轉輸入；下次觸摸接續偏移 | 放手回中；Expert 保有坡度但不鎖姿態，Assisted 由既有飛控改平。 |
| 「把橘色提前量圈疊在它身上」 | 「機頭 W 對準橘色提前量圈，再短按 GUN。」瞄本體時：「你在追它現在的位置。把機頭 W 移到橘圈，讓子彈提早到。」 |
| L05 不管實際情況，都說換掉約 2300m 高度 | 「高度實際減少 {量測值}m，速度到 {量測值}km/h」；HUD 同步顯示兩種能量餘額。 |
| 失敗時可能仍說「3 枚飛彈全部躲掉」 | 「已發射 {n} 枚，被命中 {m} 枚」；給下一次看距離／接近時間的修正。 |
| L10 一般 CLEAR／口頭恭喜 | 「確認，ACE {級別} 級資格通過。{耐久} 耐久帶回來了。這次由你領航。」加授證徽記與 S 挑戰目標。 |

教官的幽默服務於因果，不隨機稱讚。例如 MIL 一圈：「第二圈還想飛，就別把速度全花光。」失敗結算延遲由 2.4s 減至 0.8s，仍可直接重試同一課，不重播簡報；結算操作列固定在可捲動面板底部。

## 驗證、差異與限制

基準 Node 飛控、動力、四模式、學院與自由對戰測試先通過，40 個課程／模式結果收錄於 [baseline JSON](academy-controls-baseline.json)。基準 Chromium 四模式與兩場完整對戰的功能斷言通過，但有預設 favicon 404，整體報告因此 exit 1；本輪測試伺服器對該路徑回覆有效 204，沒有濾掉 console／page 錯誤。

- **完整 Node CI 命令**：既有 airbrake／power-strip／brake-trap／flight-path／HUD／A-B／dual-modes／flight-polish、`test-academy.mjs`、新增 `test-academy-coaching.mjs`、原有五組 AI 配對各三場與 flight probe。
- **課程**：L01–09 × 四模式全部通過；L10 固定開局四模式均有明確結局。Arcade／Expert 仍在 **107.72s 敗北**，沒有換種子使它贏；其餘是 S／117.23s、A／244s、B／111.38s，和基準一致。十二開局勝場仍為 **8／6／6／12**，證明各模式可通關，不宣稱單一開局必勝。
- **錯誤學員**：原程式實際是 **48 組**，初版文件誤寫 52。本輪完整保留 48 組，再新增四模式 L08 瞄本體，共 **52 組以正確原因失敗**。另加連續穩定、200m 高度門檻、三次 overshoot 判定、提早機砲糾正、失敗不假稱讚、過期字幕清除測試。
- **L09 轉移測試**：完整關卡保留原始射擊與反咬配置；獨立飛彈段用 **1.9／2.05／1.75km** 及 **1.25／6.75／14.25s** 的排程參數，四模式原學員都通過，未改 seed 或命中門檻。發射仍等待上一枚不活躍，故實際時間不一定等於排程間隔。任意改完整關卡幾何會連帶改變後段 BFM 起始狀態，本輪不把這種未校準難度變動混進正式課程。
- **Chromium**：本機 Chromium 154、Playwright 1.56.1、SwiftShader；六種既有／新增情境為 settings、manual、touch、modes、academy、academy-ui。academy 包含十課 UI、故意失敗／直接重試、進度重整、L10 與 Node 同種子逐位比對。
- **CI 版面取樣差異**：遠端曾在 667px／L01 的 HUD 邊界斷言失敗。本機固定等 90ms 的測試未重現；現改為清掉前幀量測，等待本階段 HUD／字幕實際繪製後才檢查，沒有放寬任何版面或飛行斷言。六倍 CPU 降速的 50 次版面檢查也通過，失敗時另輸出量測值與 viewport 供診斷。
- **手機版面**：812×375、667×375，25 階段 × 兩尺寸共 **50 次**檢查；自動學員先飛到該階段再凍結畫面量測。任務字 ≥12 CSS px，KITE ≥14px、最多兩行、不截字，文字區不蓋中央姿態區。已人工查看能量、追擊／機砲及授證畫面。

重現：在 `prototypes/ace-to-ace` 執行上述 Node 測試；瀏覽器先安裝 `playwright@1.56.1` 與 Chromium，再執行 `node tools/browser-check.mjs --scenario academy-ui` 等。若使用已安裝的系統 Chromium，可設定 `ACE_CHROMIUM_PATH`，不影響 CI 預設的 Playwright 瀏覽器。本輪已將新教學契約及手機版面測試加入原有 GitHub Actions。

**仍需 iPhone Safari 實機**：雙拇指回中／反向改平的手感、touchcancel 與 App 切換、系統手勢／瀏海安全區、字幕閱讀節奏、觸控延遲與效能。自動學員可完成不等於真人已學會；下一次真人測試應要求新手在沒有教官逐字提示時，解釋 W／FPM、滾轉後如何維持高度、為何瞄提前點，再嘗試新幾何。沒有新增語音、3D 資產、操作按鈕、框架或伺服器。
