## 0. 一頁結論

1. **玩家不是英雄的原因，不該是火力不足，而是分身乏術。** 玩家在局部戰鬥可以很強（保留 Ace Combat 的爽感），但戰區同時有 3–5 個爭奪點在走時鐘，他只能在一個地方。限制玩家的是「在場的稀缺性（Scarcity of Presence）」，不是殺傷力。
2. **戰場的基本單位是「爭奪點（Contest）」，不是任務，也不是單位。** 每個爭奪點有賭注、時鐘、勝負平衡與後果。玩家的核心策略選擇是「去哪裡、待多久、什麼時候回去補給」。
3. **AI 的聰明只有被看見時才存在。** 整個 AI 以真實空戰簡令（Brevity Code：COMMIT、NOTCH、BRACKET、SKATE…）作為內部決策語言。AI 的每個決策本身就是一句無線電，所以「可讀性」不用另外做，是架構本身就帶的。
4. **遠方的戰爭用「校準過的抽象模擬」跑，近處才用完整飛行模擬。** 抽象模型的係數由上萬場無頭（headless）實機模擬擬合而來，所以兩者在統計上一致。這讓戰爭可以在玩家看不到的地方繼續，又不燒掉手機的 CPU。
5. **導演系統不作弊，只做「在合理的未來裡挑一個」。** 它不能憑空生出敵機，只能在玩家**沒有觀測到**的戰場上，從 K 個真實取樣的結果中挑出最符合節奏曲線的那一個。K=1 就是純模擬模式。
6. **對手是撲克牌手，不只是棋手。** 雙方指揮官在不完全資訊下用混合策略分配兵力（Colonel Blotto 型賽局），輸的一方會因展望理論（prospect theory）變得願意冒險，「孤注一擲」因此自然出現，翻盤不靠作弊的橡皮筋機制。
7. **每場出擊結束，用同一套抽象模擬回答「我的選擇有沒有差」**（反事實簡報）。這是讓「AI 友軍也能獨立取勝」不至於讓玩家覺得自己多餘的關鍵。
8. **市場判斷：** Ace Combat 8: Wings of Theve 已於 2026/10/02 上市，題材同樣是「奪回家園」加上三名僚機的小隊指揮，但評論指出任務成敗大致不受僚機指令影響（TechRadar）。Skyfront 不該和 Bandai Namco 拼演出預算，**該拼的是「戰局真的會因為你、也會不因為你而改變」**。

## 1. 先問為什麼好玩

### 1.1 玩家喜歡空戰，其實是喜歡這四件事

| 動機 | 在空戰裡長什麼樣子 | 常見設計失誤 |
|---|---|---|
| **掌握感（Competence）** | 能量管理、在對的時機出手、躲掉一發飛彈後反咬回去 | 敵人只是標靶，掌握感沒有對手可以驗證 |
| **讀懂對手（Reading）** | 看出敵機要包夾、看出誘餌、看出他沒油了 | AI 沒有可讀的意圖，只有突然的行為 |
| **歸屬（Relatedness）** | 僚機救了你、你救了僚機、整個中隊一起回家 | 僚機是裝飾，死了也沒有後果 |
| **有故事可講（Story）** | 「那天我們在河谷下面被埋伏，Kite 跳傘，我們把他搶回來了」 | 劇情全部是腳本，每個人講的故事都一樣 |

前三項對應自我決定論（Self-Determination Theory）的勝任、自主與關聯；第四項是重玩價值的真正來源：**玩家會一直回來，是為了得到一個新的故事，不是為了重刷同一個關卡。**

### 1.2 現有作品在哪裡斷掉

| 作品／類型 | 做對了什麼 | 斷點 |
|---|---|---|
| Ace Combat 系列（含 AC8） | 爽快操作、電影感、王牌敵機、音樂與無線電戲劇 | 戰場像射擊遊樂場；戰局由腳本決定，僚機指令對結果影響小 |
| Falcon 4.0 動態戰役 | 真正會自己進行的戰爭 | 太不透明，玩家不知道自己做的事有沒有意義 |
| DCS（及 Liberation／Retribution 等動態戰役生成器） | 可信的武器與飛行 | 門檻高；AI 薄弱；戰場多半是靜態的 |
| 真・三國無雙 | 多戰線同時告急，玩家被迫「選擇去救誰」 | 敵兵是草，選擇只關乎時間，不關乎判斷 |
| Left 4 Dead AI Director | 用張力曲線控制節奏 | 靠憑空生怪，放在可信戰場裡會破壞可信度 |
| RimWorld 說書人 | 人格化的事件節奏 | 事件直接降臨，不受世界狀態約束 |
| Highfleet | 雷達發射、截聽與偵測就是玩法 | 小眾、操作抽象 |
| XCOM | 士兵永久死亡帶來強烈情感投入 | 回合制，無法直接搬來 |
| Helldivers 2 銀河戰爭 | 全體玩家共同推動的持續戰線，加上真人 Game Master 調整 | 需要營運團隊；不適合單人 |
| Nuclear Option | 動態大戰場加上 SimCade 手感，口碑很好 | 戰場目前偏「大」而不偏「故事」，單人內容仍在擴充 |

結論：**沒有人同時做到「可信的自主戰場」與「玩家看得懂且有意義的選擇」。** 這就是缺口。

### 1.3 我對願景的五個挑戰

**挑戰 A：「戰爭不會因為玩家沒有介入而停止」→ 只在出擊期間成立。**
全域連續即時的戰爭，會讓玩家錯過最精彩的部分，讓手機的遊玩時段無法切分，讓存讀檔變複雜，也讓 AI 成本膨脹。建議：**出擊（Sortie）期間戰爭全速即時進行；出擊之間用「戰爭日（War Day）」回合推進。** 戰爭依然自主，只是有了呼吸的節點。Falcon 4 的連續戰役證明了自主戰場可以做到，也證明了它對大多數玩家太難消化。

**挑戰 B：「玩家不是超級英雄」→ 不要用削弱玩家來實現。**
如果用降低玩家殺傷力來實現「非英雄」，會直接殺掉 Ace Combat 的爽感。正確做法是讓**玩家在局部可以是英雄，在全局只是一個人**。他可以在河口打下六架，但同一時間雷達站在河谷那邊失守了。

**挑戰 C：「像下棋般博弈」→ 資訊上是撲克，節奏上才是西洋棋。**
西洋棋是完全資訊賽局，意外只來自計算深度。空戰的意外來自**看不見的東西**：埋伏、佯攻、雷達靜默、虛張聲勢。所以要讓雙方 AI 都活在戰爭迷霧裡，也要讓 AI 會欺敵、會被騙。節奏上借用西洋棋的概念：**每一發飛彈都是一次「將軍」**，強迫對手回應。

**挑戰 D：「AI 友軍也能獨立取得勝利」→ 必須可歸因。**
友軍能自己贏，玩家就可能覺得自己多餘；友軍贏不了，「非英雄」就是假的。解法是讓玩家的貢獻**可以被量化並呈現**（第 5.4 節的反事實簡報），並把設計目標訂在：**玩家參與一個爭奪點，能把勝率拉動 15–30 個百分點。** 有感，但不至於決定一切。

**挑戰 E：PvPvE 是另一個產品。**
單人核心不應該為了多人的需求（決定性同步、公平性、導演關閉）而提早妥協。但有一個便宜的保險應該從第一天就買：**核心模擬做成可無頭執行、可放在伺服器上跑的獨立模組。**

### 1.4 五個設計支柱

1. **可讀的智慧（Legible Intelligence）**：AI 的每個重要決定都必須有玩家看得到或聽得到的徵兆。
2. **同一套規則（Same Rules）**：AI 和玩家共用飛行模型、G 限制、感測器規則與戰爭迷霧。不給超機動，也不給全知視角。
3. **分身乏術（Scarcity of Presence）**：玩家最稀缺的資源是「在場」，而不是彈藥。
4. **每發飛彈都是一次將軍（Every Missile is a Check）**：飛彈可以很多，但每一發都迫使對方付出能量、位置或攻擊機會。
5. **後果會留下（Consequences Persist）**：被擊落的人、失守的雷達、燒掉的油，都會帶到下一個戰爭日。

## 2. 核心玩法迴圈與重玩結構

### 2.1 三個時間尺度的迴圈

```text
秒級（纏鬥）     能量是貨幣，飛彈是提問，讀出意圖，抓住破綻
  │
分鐘級（出擊）   在戰場天氣圖上選擇爭奪點，管理彈藥／油料與時間，對僚機下達意圖，向指揮部提出請求
  │
戰爭級（戰役）   8–12 個戰爭日；雙方指揮官重新規劃；損失持續存在；戰爭以勝、敗或停火收場
```

**秒級：把 BVR 當成格鬥遊戲的立回（footsies）。**
超視距階段像格鬥遊戲的立回：距離、出手時機、逼對方先動。一發飛彈逼對方 NOTCH（切向躲避）或 DRAG（轉身拉開），他就失去能量與接近率，這時你 PRESS（繼續壓上），他就陷入被動。合併（merge）之後進入纏鬥，比的是能量與角度。
允許大量飛彈（遊戲化），但飛彈的命中率取決於距離、目標能量與目標是否正確防禦。**低命中率的飛彈仍然有價值，因為它是施壓工具**，會提升對手的壓力值（見 4.3 節），讓他犯錯。

**分鐘級：玩家的核心策略選擇。**
- **去哪裡**：戰場上同時有 3–5 個爭奪點，各有時鐘與賭注。
- **待多久**：彈藥與油料有限。回基地或找加油機要花時間，而時間就是其他爭奪點的勝負。
- **對僚機下達「意圖」而不是「指令」**：COVER ME、TAKE THE BOMBERS、BRACKET、GO HOME。僚機會依技術與個性詮釋。
- **向指揮部「請求」**：「請求對三號陣地實施 SEAD」。請求是否被接受，取決於資源與玩家的聲望（Clout）。聲望來自守住爭奪點與救援，而不只是擊落數，用來鼓勵玩家為團隊而戰。

**戰爭級：一場戰爭就是一輪（Run）。**
- 一場戰爭約 3–5 小時，分成 8–12 個戰爭日，每天一次出擊（PC 12–20 分鐘，手機模式 8–12 分鐘）。
- 戰爭日之間：雙方指揮官重新規劃，損失結算，中隊休整，觸發劇情片段（Storylet）。
- 戰爭結束後：解鎖機體與中隊傳統，提高難度階梯（指揮官人格加戰區條件，類似 Hades 的 Heat）。

### 2.2 重玩價值的來源

| 來源 | 機制 | 為什麼不會變成重複 |
|---|---|---|
| 指揮官人格 × 混合策略 | 每天的兵力分配從均衡混合策略中抽樣 | 對手在理性範圍內不可預測 |
| 戰區條件 | 季節天氣（東北季風、梅雨、颱風前夕）、日夜、初始兵力 | 同一張地圖的地形價值會改變（雲層會遮蔽低空突穿） |
| 中隊名冊 | 僚機成長、受傷、陣亡、被俘、彼此的羈絆 | 每場戰爭的人都不同 |
| 宿敵王牌 | 有限數量的敵方王牌，各有可學習的習慣（tell），也會記得你 | 第三次交手和第一次不同 |
| 玩家習慣模型 | 敵方指揮官會研究你常做什麼 | 你不能用同一招打完整場戰爭 |
| 情境模板 | 由模板與種子生成的戰爭開局 | 組合空間大 |
| Storylet | 以世界狀態為條件觸發的角色片段 | 劇情跟著你的戰爭走 |

### 2.3 容易上手：一套語言，兩層意思

- 無線電使用真實簡令（例如「Lancer 2, NOTCH right!」），字幕同時給出白話（「右切，躲雷達導引」）。軍事迷聽得出可信度，一般玩家看得懂意思。
- **教練模式**：AI 用來替自己挑選動作的同一個評估器，也可以替玩家評估，在 HUD 上給出建議（例如「建議：CRANK 左」）。新手當作教學，老手可以關掉。
- **動作輔助（手機特別重要）**：玩家可以直接點一個動作（NOTCH、EXTEND、BREAK），由 AI 使用的同一個飛控執行器代為飛出來。這樣手機版不需要完整的雙搖桿操作，也能打出有戰術意義的空戰。

這和 repo 現有的哲學一致：幾何管線是「渲染器無關的 WorldModel → 引擎轉接」，戰場引擎也應該是「無頭核心 → 引擎轉接」。

### 3.1 簡令語法：整個引擎的共同語言

每個動作（Play）都是一筆資料，同時服務八個用途：

```text
Play: CRANK
  前置條件: 已發射導引中的飛彈，目標在雷達範圍內
  評估特徵: 飛彈剩餘導引時間、接近率、我方能量、敵方是否已發射
  執行器:   偏置航向 40–55°，維持雷達鎖定，降低接近率
  無線電:   "{callsign}, cranking {dir}."  ／ 白話字幕：「側轉維持導引，拉開距離」
  可見徵兆: 航跡出現穩定側偏；對方 RWR 鎖定持續
  失誤型態: 側轉角度過大導致失鎖（新手、高壓）
  遙測標籤: play.crank
```

| 用途 | 怎麼使用同一筆 Play |
|---|---|
| 1. AI 決策 | 飛行員層從中選擇動作 |
| 2. 無線電戲劇 | 決策本身就是一句無線電 |
| 3. 可讀性徵兆 | 每個動作都帶有幾何上看得出來的特徵 |
| 4. 僚機指令 | 玩家的意圖指令對應到動作或任務 |
| 5. 教練提示 | 用同一個評估器評估玩家的處境 |
| 6. 手機動作輔助 | 用同一個執行器代飛 |
| 7. 導演張力特徵 | 用動作頻率與種類估計戰場張力 |
| 8. 戰後敘事與測試 | 故事帳本與 Battle CI 都以動作為事件單位 |

語法以美軍多軍種簡令（Multi-Service Brevity Codes, ATP 1-02.1）為藍本，遊戲內可微調。初版約 25–35 個動作與呼號就足夠，見附錄 A。

**這是整份提案裡投資報酬率最高的一個決定：** 少做一層「把 AI 狀態翻譯成玩家看得懂的東西」，因為 AI 本來就用玩家看得懂的語言思考。

## 4. AI 如何彼此博弈

### 4.1 戰區指揮官（L1）：在迷霧中打一場 Colonel Blotto

**問題本質。** 每個戰爭日，雙方都要把有限的編組（掃蕩、護航、打擊、SEAD、CAP、預警機、加油機、救援）分配到多個爭奪點。這就是 Colonel Blotto 賽局：在多個戰場上分配有限資源，總勝場數決定結果。純策略必然會被針對，所以理性的對手會使用**混合策略**。

**做法：**
1. **方案由模板組成**：設計師編寫 20–40 個「戰略方案模板」（北方佯攻加河谷低空打擊、正面強攻、縱深防禦、全力一擊……），每個方案都是可讀的（「今天紅軍的計畫：北佯南打」）。
2. **報酬由抽象模擬計算**：每對（我方方案 × 敵方方案）用校準過的爭奪點解算器跑 Monte Carlo（例如每格 32 次）。40×40 的報酬矩陣大約是 5 萬次抽象解算，每次在微秒等級，**在戰爭日之間的讀取畫面內就能完成，手機也可以**。
3. **求解用 Regret Matching**：收斂到近似均衡的混合策略，再從中**抽樣**一個方案執行。意外由此產生，而且是理性的意外。
4. **人格由效用函數表達，而不是腳本**：
   - **展望理論價值函數**：參考點是「預期中此時應有的戰況」。落後時處於損失區，損失規避係數 λ 讓指揮官**偏好高變異的方案**，也就是國際關係文獻裡的「孤注一擲以求翻身（gambling for resurrection）」。這是不作弊的翻盤機制。
   - **欺敵傾向**：提高含佯攻、誘餌的方案權重。
   - **耐心、教條偏好**：例如偏好先打 SEAD、偏好保護高價值資產。
5. **對手模型**：用虛擬對局（fictitious play）式的計數，記錄對方過去的方案傾向；其中一個子模型是**玩家習慣模型**（玩家常去哪類爭奪點、常在什麼高度交戰、被鎖定時常往哪邊破）。
6. **出擊中微調**：每 20–30 秒依爭奪點的平衡變化重新分配預備隊；命令有傳遞延遲，延遲本身會創造可利用的窗口。

### 4.2 爭奪層（L2）：戰場的原子單位

一個爭奪點包含：

- **區域**：一塊空域體積與地面目標；
- **賭注**：獲勝或失敗會改變什麼（雷達覆蓋、加油航線、跑道可用率、救援人員）；
- **時鐘**：有效時間窗；
- **平衡**：B ∈ [−1, +1]，以及動量 dB/dt；
- **參與者**與**解析結果**。

**類型**：空優、打擊與防禦、SEAD、高價值資產保護（預警機、加油機）、救援（CSAR）、攔截（巡弋飛彈與無人機群，這是讓玩家刷擊落數、保留 Ace Combat 爽感的目標密集型爭奪點）、護送。

**爭奪點內的協調：用拍賣。**
指揮部公告任務，各編隊依距離、能量、武器與風險出價，得標者執行（合約網協定，以及 CBBA 這類一致性拍賣演算法的簡化版）。無線電會這樣說：「Viper 2，北邊那組我來。」
**電子戰會干擾通訊，拍賣訊息因此遺失或過期**，結果是重複鎖定同一目標、出現防守空隙。電子戰因此自然降低了 AI 的協調品質，不需要另寫特例程式碼。

### 4.3 飛行員層（L3）：可信、會犯錯、遵守同一套物理

**感知**：只讀己方的空情圖（Picture）與自身感測器（雷達錐、目視、RWR、ESM），不讀真實世界狀態。這一點由 Battle CI 強制檢查（第 5.5 節）。

**決策**：每 0.1–0.3 秒（反應時間取決於技術）評估當前階段（BVR、合併、WVR、防禦、脫離）可用的 6–10 個動作：

```text
U(play) = 賭注急迫度 × Π_i 反應曲線_i(特徵_i) × 人格偏好
特徵：能量優勢（比剩餘功率 Ps 差）、天線偏角／視角、距離相對飛彈包絡、
      空中飛彈、僚機狀態、油料／彈藥、威脅數、可用地形遮蔽、爭奪點時鐘
選擇：softmax(U / τ)，加上承諾的遲滯（避免抖動；偵測到飛彈發射時才可打斷）
```

乘法型效用（類似 Infinite Axis Utility System）的好處是：任何一個特徵歸零，就能否決整個動作，容易除錯與調整。

**執行**：動作 → 機動目標（期望速度向量、升力向量、油門）→ 飛控（PD／LQR，作用於街機化飛行模型）→ 操縱輸入。**與玩家完全相同的 G、攻角與能量損失限制。**

**失誤模型：壓力值 S ∈ [0, 1]**

```text
S 上升：飛彈警告、附近有友機被擊落、持續高 G、以寡擊眾、油料告急、長機陣亡
S 下降：僚機支援、一段時間沒有威脅、「冷靜」特質
效果：  決策溫度 τ = τ0(技術) + k·S          → 選擇變得更隨機
        注意力上限 = Amax·(1 − 0.6·S)        → 同時追蹤的航跡數下降（6 → 2）
        反應延遲 = d0·(1 + S)
        特質化失誤：追頭（積極型）、過早脫離（謹慎型）、目標分配錯誤（新手）、
                    過早防禦（緊張型）、超 G（菜鳥）
```

**玩家可以「製造」敵人的壓力**：用飛彈施壓、從地形遮蔽後突然出現、先打掉長機讓編隊瓦解。這讓「每發飛彈都是一次將軍」有了可量化的機制。

**技術分級**（新手、一般、資深、王牌）的差異在於反應時間、對飛彈包絡判斷的準確度、抗壓性與動作庫大小，**而不在物理上**。

### 4.4 資訊戰：誰看見誰

- 每一方維護一張**空情圖**：每條航跡帶有位置不確定性與識別信心。
- 來源：預警機、地面雷達（**會被台北盆地周圍的山遮蔽**，例如陽明山、觀音山、林口台地）、戰機雷達（開機會暴露自己）、被動 ESM／RWR（只有方位）、目視。
- **截聽**（遊戲化的訊號情報）：若己方的訊號情報機存活，玩家可以聽到經過翻譯的敵方無線電片段。這是一個可讀性管道，也是一個值得保護的爭奪點。
- 打掉預警機或雷達會降低對方的空情圖品質，進而讓指揮官分配失誤。**後果透過資訊傳遞，不需要寫特例。**
- 欺敵對雙方都有效：低空貼地、雷達靜默、誘餌編組、佯攻。

## 5. 突破傳統空戰遊戲的新想法與工程方法

### 5.1 校準式模擬 LOD（Calibrated Autoresolve）

**是什麼。** 玩家附近的爭奪點用完整模擬（L3）；遠方的爭奪點用抽象模型，每 5 秒一個步長，以泊松過程擲出雙方損失與狀態變化。

**新意在「校準」。** 抽象模型的結構以 Lanchester 方程為先驗（平方律：dN_blue/dt = −α_red·N_red …），係數則依特徵調變：機型組成、平均技術、剩餘飛彈、能量姿態、資訊優勢（預警機覆蓋率）、地形遮蔽比例、能見度與電子戰。係數由 **10⁵–10⁶ 場無頭實機模擬擬合而來**。

**簡單說：Lanchester 提供結構，數據提供係數。** 模型保持小而可解釋（分桶查表或小型梯度提升樹，小於 1 MB），並以飛行模型與武器資料的雜湊值鎖定版本，任何平衡改動都會使其失效，必須重新擬合。

**物化與去物化。**
- 當玩家預計 60–90 秒內抵達某爭奪點時，引擎把抽象狀態**物化**成具體飛機：位置與己方空情圖上的最後已知航跡一致，數量、彈藥、油料與抽象狀態一致，生成位置在目視距離之外。
- **先出現航跡，才出現機體**：玩家先在雷達上看到它們，永遠不會看到飛機憑空冒出來。
- 玩家離開時，具體狀態彙整回抽象狀態。

**一致性閘門**：從相同起始狀態出發，比較抽象與具體的結果分佈（勝率差 < 5 個百分點、損失數分佈的 KS 檢定通過），否則不允許發布。

### 5.2 命運取樣器（Fate Sampler）：不作弊的導演

**問題。** 自主模擬常常產生無聊的結果（雙方互相消耗）或混亂的結果（三個高潮同時發生）。Left 4 Dead 的導演用生怪解決，但在可信戰場裡生怪就是作弊。

**機制。**
1. 導演維護一條**目標張力曲線**：出擊級是「累積 → 高峰 → 釋放」，戰爭級則逐日升高。
2. 張力估計器 T(t) 使用以下特徵：威脅與玩家的距離、來襲飛彈、友軍損失率、爭奪點平衡的擺動、距離上一次高峰的時間。
3. 對**玩家沒有觀測到**的爭奪點，抽象解算時取樣 K 個結果（都是模型下真實可能的樣本），預測各自未來 H 秒的張力軌跡，**選擇最貼近目標曲線的那一個**。
4. 允許的槓桿：
   - 未觀測爭奪點的取樣選擇；
   - 情報抵達的延遲（在合理的 10–60 秒範圍內）；
   - 哪些無線電事件會優先播給玩家；
   - 天氣在預報錐範圍內的取樣（只在預報更新、尚未被觀測時）。
5. **禁止事項**：生成戰鬥序列以外的單位、改變玩家已觀測的航跡、改變任何涉及玩家的射擊命中率、改血量或彈藥、讓 AI 故意失誤。
6. **觀測帳本**：記錄玩家觀測過的一切。任何選擇都不得與帳本矛盾。
7. **偏差稽核**：目標函數只看節奏，不看輸贏。並由 Battle CI 量測「導演開與關」對玩家戰爭勝率的影響，必須小於設定上限（例如 3 個百分點）。
8. **純粹模式 K=1**：完全不介入。多人 PvP 強制 K=1。

**為什麼比傳統導演好**：它從頭到尾只在「本來就可能發生的事」裡做選擇，玩家永遠找不到違反世界規則的證據。這是「未觀測寬容度」的工程化版本。

### 5.3 戰場天氣圖（Battle Weather Map）

把影響力地圖（influence map）**畫成天氣圖**：

| 天氣圖元素 | 戰場意義 |
|---|---|
| 高氣壓與低氣壓 | 我方或敵方的空中控制 |
| 鋒面 | 爭奪點的邊界與推進方向 |
| 雷暴胞 | 正在進行的交戰（強度 = 張力） |
| 風向箭頭 | 動量 dB/dt |
| 霧 | 空情圖的不確定性（預警機被擊落時，地圖真的會「起霧」） |
| 預報錐 | 依己方空情圖推估的敵方意圖 |

一般玩家天生就會讀天氣圖，例如「紅色雷暴正往基隆移動」。軍事迷可以切換成 APP-6 風格的軍事符號。**這張圖使用的資料就是己方指揮官 AI 看到的資料，所以 UI 是誠實的**，玩家和 AI 看到同一張戰場。

### 5.4 反事實簡報（Counterfactual Debrief）

- 在決策點建立快照：玩家進入或離開爭奪點、重大選擇。
- 出擊後，從快照用抽象模型跑 N≈200 次推演，在其中移除玩家的影響（或替換為一名典型友軍飛行員）。
- 呈現方式：「你在淡水河口造成的差異：守住機率 +27 個百分點（±6）」，以及「你沒選擇的那條路：如果你留在雷達站，它存活的機率是 74%，而不是 31%」。

心理學上，這同時處理三件事：**選擇有意義**（自主感）、**學習**（下次看得懂誘餌）、**歸因**（友軍自己贏時，玩家知道那是他們的功勞，也知道自己的貢獻在哪裡）。峰終定律提醒我們：一場出擊的最後一分鐘（簡報）會決定玩家對整場的記憶。

工程上幾乎免費，因為它重用 5.1 節的抽象解算器。必須以機率呈現，不能寫成斷言。

### 5.5 Battle CI：把 repo 現有的閘門文化搬到 AI 上

這個 repo 已經有很成熟的「決定性、失敗即關閉（fail-closed）、雜湊鎖定」幾何閘門。戰場 AI 應該沿用同一種紀律：

| 閘門 | 內容 |
|---|---|
| 公平性 | AI 超 G 次數 = 0；AI 讀取真實狀態（而非空情圖）的次數 = 0（由 API 邊界強制） |
| 校準 | 抽象與具體的結果差異在門檻內 |
| 平衡 | 機型對戰勝率在設定區間；沒有支配性策略（用強化學習代理當「對抗測試員」找漏洞） |
| 可讀性 | 每個動作都產生可觀測的徵兆；無線電與實際行為一致 |
| 戲劇性 | 每場戰爭的領先易手次數、「死寂時間」上限、第三天前就分出勝負的比例 |
| 導演偏差 | 導演開／關的勝率差在上限內 |

**強化學習只當測試員，不當飛行員**：用它找設計漏洞，不把策略網路放進執行期。DARPA AlphaDogfight（2020）已經證明強化學習代理能學會極強的空戰，但它的行為難以解讀、難以調整，也很會鑽模擬的漏洞。這些正是遊戲不想要的特性。

### 5.6 中隊與宿敵（並刻意避開 Nemesis 專利）

- **中隊是主角**：僚機有名字、特質、成長、疲勞、羈絆；可能陣亡或被俘（可選擇關閉永久死亡）。
- **跳傘會自動生成救援爭奪點**，雙方指揮官依各自的教條決定是否投入兵力搶人（見情境二）。救援、撤退與犧牲都由模擬事件產生，不靠腳本。
- **宿敵檔案**：少量（每場戰爭 3–6 名）手工設計原型的敵方王牌，各自帶程序化變化的習慣（tell）與交手記憶。
- **智慧財產風險**：華納兄弟的 Nemesis 專利（US 10,926,179，2021 年核准；媒體估計到期日為 2035–2036 年）涵蓋了 Shadow of Mordor 式的敵人階層、晉升與仇恨系統。本提案刻意**不做**敵方階層、晉升或追隨者結構。即便如此，定案前仍需法律審查。

### 5.7 Storylet：在動態戰爭上掛載手工角色戲

用帶條件的劇情片段（Failbetter 式的 storylet，以及 Hades 那種依優先級排序、條件觸發的對白），例如「中隊第一次失去成員時」、「Kite 被救回之後的第一次出擊」、「紅軍指揮官進入孤注一擲狀態時」。這樣可以用小成本得到 Top Gun 式的角色時刻，而劇情永遠跟著玩家自己的戰爭走。

### 5.8 Claude／GPT 在開發期的角色（執行期為零）

1. **生成無線電台詞變體**（動作 × 人格 × 壓力等級），經人工篩選後離線配音或 TTS；
2. **起草戰略方案模板與情境模板**，由設計師審核；
3. **把 Battle CI 的大量戰鬥紀錄摘要成故事**，讓設計師快速判斷哪些戰爭無聊，並作為「戲劇評審」協助調整導演的目標函數（人在迴圈中）；
4. **協助撰寫與審查引擎程式碼**。

執行期不使用任何大型語言模型或神經網路策略。

## 6. 具體空戰情境

設定：台北北部戰區，冬季。陣營為抽象的**藍軍**（Homeland）與**紅軍**（虛構對手）。玩家呼號 Lancer 1，僚機 Lancer 2「Kite」（特質：積極）。

### 情境一：觀音山下的誘餌

**戰爭日 4，06:40。東北季風：北海岸雲底 600 m，基隆河谷有毛雨；台北盆地與海峽上空晴朗。**

**戰場狀態（天氣圖）**
- **C1 淡水河口空優**：賭注是保護我方位於林口台地後方的加油機航線。
- **C2 基隆河谷低空雷達站**：賭注是我方北部的低空雷達覆蓋。
- **C3 海峽上空 4 架紅軍轟炸機**：賭注是如果放行，下一個戰爭日我方前進基地的出擊架次減少 25%。

**紅軍指揮官**（人格：詭道型，欺敵 0.8，λ=2.1）用 regret matching 求出今日的混合策略：「北佯南打」0.35、「海峽正面強攻」0.40、「全面防守」0.25。
玩家習慣模型提高了誘餌方案的期望報酬：在戰爭日 1–3，玩家只要看得到打擊編組就去追，3 次裡 3 次。
抽樣結果是**「誘餌」方案**：
- C3 的轟炸機是誘餌，觀音山後方有 4 架戰機以雷達靜默低空待命；
- 真正的打擊是 2 架攻擊機，在雲層下方沿著基隆河谷貼地前往 C2。

**06:41:20｜一個新手的失誤成為破綻**
紅軍埋伏編隊的 3 號機是新手，壓力 0.42，**提早開了 4 秒雷達**（特質化失誤：緊張型）。藍軍 ESM 收到一次短暫的發射訊號。
預警機呼叫：「Lancer, Magic. Picture: single group, four, heavy, hot. Note—pop-up emitter vicinity Guanyin, unknown.」
天氣圖上，觀音山附近出現一個小小的低壓擾動。

**分支 A：玩家照習慣追轟炸機**

紅軍埋伏長機在 06:43 的決策評估（示意）：

| 動作 | 效用 | 主要因素 |
|---|---|---|
| PINCE（鉗形夾擊） | **0.71** | 藍軍專注於轟炸機、突襲值 0.8、有地形遮蔽 |
| HOLD（靜默等待） | 0.62 | 尚未進入最佳包絡 |
| BRACKET | 0.58 | |
| SKATE | 0.44 | |

- 紅軍選擇 PINCE。預警機呼叫：「New group, low, bearing 210, 15 miles, hot—BANDITS!」
- Kite（積極型，壓力 0.55）發生**追頭失誤**，繼續咬著轟炸機不放。玩家被迫轉入防禦。
- 玩家打下 2 架轟炸機與 1 架戰機（爽感有了），但 Kite 中彈跳傘（接情境二）。
- 同一時間在 C2：2 架攻擊機在雲下突穿，我方 2 架一般等級的 CAP 攔截太晚，**雷達站被摧毀**（抽象解算，玩家沒有觀測到）。
- 後果：下一個戰爭日，北部低空空情圖變差，紅軍的低空突穿成功率上升。

反事實簡報：

```text
你的選擇：C3 轟炸機
  · 前進基地跑道受損機率      81% → 46%（你造成 −35 pp）
  · C2 雷達站存活率            31%
你沒選的路：守在 C2
  · C2 雷達站存活率            74%
  · 跑道受損機率               58%（友軍 CAP 仍可能攔下部分轟炸機）
附註：06:41 觀音山附近的短暫發射訊號，是紅軍埋伏編隊的徵兆。
```

**分支 B：玩家讀出了徵兆**

玩家下令：「Lancer, BRACKET the bombers, stay high, check the pop-up.」我方保持 1,800 m 的高度優勢與速度。
紅軍長機的評估隨之改變：能量劣勢 −0.45，ESM 已暴露所以突襲值降為 0.3。

| 動作 | 效用 |
|---|---|
| SKATE（遠距發射後轉離） | **0.57** |
| BUGOUT | 0.41 |
| PINCE | 0.38 |

- 紅軍改為 SKATE。如果我方截聽機存活，玩家會聽到翻譯後的敵方片段：「…目標太高，放棄夾擊，發射後脫離…」。
- 埋伏被翻轉，轟炸機失去掩護。玩家可以收割轟炸機，或抽身前往 C2，因為**時間現在站在玩家這邊**。

**這個情境展示了**：混合策略加上對手模型帶來合理的意外；新手失誤成為可讀的徵兆；局部勝利與全局損失可以同時發生；反事實簡報讓玩家學會「下次看懂」。

### 情境二：Kite 跳傘了

**06:44，汐止上空，基隆河谷，雲底 600 m，毛雨。**

1. 故事帳本記錄「Kite 跳傘」，**自動生成救援爭奪點 C4**：時鐘約 15 分鐘，之後被俘風險急升。
2. **藍軍指揮官**的效用評估：人員價值（技術、士氣影響）高於風險 → 派出盆地內待命的救援直升機，需要護航。
3. **紅軍指揮官**（教條：俘獲高價值飛行員）把 2 架原本要支援 C1 的戰機轉往 C4。這是 Blotto 賽局裡的取捨：**C1 因此變弱了**。
4. 天氣成為戰術變數：直升機只能在雲下沿河谷低飛。紅軍戰機在雲上無法目視，只能靠雷達下視。玩家必須選擇：
   - 下到雲下貼身護航：風險高，但可以直接保護直升機；
   - 留在雲上攔截紅軍戰機，切斷他們的下視機會：效率高，但直升機暴露在任何漏網之魚面前。
5. **導演介入（命運取樣器，K=3）**：
   張力剛經歷埋伏的高峰，目標曲線要求先有 60–90 秒的釋放，再升向救援高潮。導演對玩家**沒有觀測到**的 C1 取樣接下來 2 分鐘的三個結果：
   - (a) 紅軍掃蕩在 06:46 突破 C1，立即威脅加油機：兩個高峰重疊，偏離目標曲線；
   - (b) C1 僵持；
   - (c) 紅軍掃蕩撤退：對玩家最有利。

   導演選擇 **(b)**，並寫入帳本。注意，它**沒有選擇對玩家最有利的 (c)**，因為目標函數只看節奏。
6. 玩家的資源：剩 6 發飛彈，9 分鐘後油料到 Joker。留下來護航，就必須依賴 C1 的加油機，而 C1 的狀態又取決於前面的選擇。三個爭奪點因此串在一起。
7. 結果：
   - 救援成功：Kite 下一個戰爭日歸隊，獲得「生還者」特質（抗壓 +），中隊士氣上升，並觸發 storylet。
   - 救援失敗：Kite 被俘，可能在停火談判的戰俘交換 storylet 中再次出現。

**這個情境展示了**：救援戲劇從模擬事件中長出來；天氣成為戰術地形；導演在不作弊的前提下塑造節奏；資源（飛彈、油料、時間）把多個爭奪點連在一起。

### 情境三：灰隼，第三次交手

**戰爭日 6，07:15，林口台地上空。**

宿敵檔案「灰隼」：
- 戰爭日 2，他擊落了我方 3 號機；
- 戰爭日 5，玩家打傷了他；
- 他的習慣（tell）：**低於角點速度（corner speed）時一定會轉向垂直機動**，而且喜歡從雲層上方重新切入；
- 他對玩家的記憶：玩家偏好低空水平迴轉戰，所以他會試圖把玩家拖進垂直戰。

| 時間 | 灰隼的動作 | 狀態與徵兆 | 玩家的機會 |
|---|---|---|---|
| +0 s | 迎頭合併（BLOW THROUGH） | Ps 優勢 +，高度 +600 m | 不要跟著水平迴轉 |
| +6 s | 垂直上拉（他的習慣） | 速度降到角點以下 | 預判頂點位置，改走滯後追擊（LAG） |
| +11 s | 頂點翻轉 | 速度極低，**這一刻他最脆弱** | 紅外線飛彈或機砲窗口約 2 秒 |
| +13 s | 若被識破：EXTEND 進入雲層 | 壓力 0.6，放棄並重新評估 | 不要追進雲裡（他會從雲上重新切入） |

這場交手不是腳本。灰隼的行為來自同一套效用評估，只是人格偏好把「垂直機動」的權重拉高了。**玩家學到的是這個對手的習慣，而不是關卡的記憶**。下一場戰爭，灰隼的習慣會被重新抽樣。

### 情境四：孤注一擲

**戰爭日 9，紅軍落後。**

- 紅軍的參考點是「第 6 天前取得空優」，但目前戰況遠低於參考點，處於損失區。展望理論讓紅軍指揮官偏好高變異方案，**抽樣出「全力打擊盆地指揮通訊節點」**，幾乎傾巢而出，紅軍前進基地（虛構島嶼）的防空因此空虛。
- 藍軍是否能及早偵測到大規模起飛，取決於北部雷達還在不在（**情境一的後果在這裡回收**）：
  - 雷達存活：預警時間約 6 分鐘；
  - 雷達失守：預警時間約 2.5 分鐘，防守勝率下降約 15 個百分點。
- 藍軍指揮官的混合策略：防守 0.6，加上預備隊反擊 0.4。玩家在出擊簡報中選擇加入哪一邊。

| 選項 | 友軍單獨成功率 | 有玩家時的成功率 | 意義 |
|---|---|---|---|
| A. 城市上空防空戰（信義天際線與台北 101 作為視覺地標） | 52% | 78% | 電影感最強，擊落數多；但戰爭還會繼續 3–4 天 |
| B. 夜間低空跨海反擊紅軍前進基地 | 41% | 68% | 成功時紅軍出擊能力 −60%，戰爭可能 1–2 天內結束；但城市節點有 48% 機率被擊中 |

兩個選項都是正確答案。**友軍在玩家沒去的那一邊，仍有約一半的機會自己打贏。** 戰後簡報會告訴玩家另一邊發生了什麼，以及原因。

**這個情境展示了**：翻盤來自理性的人格，而不是橡皮筋；前面戰爭日的後果會被回收；玩家面對的是兩難，而不是「最佳解」；友軍確實有能力獨立取勝。

### 7.2 效能預算（估計值，需在原型中驗證）

| 項目 | PC | 手機（中階機） |
|---|---|---|
| 玩家周圍完整模擬的飛機數 | 32–48 | 12–16 |
| 同時在空中的飛彈 | 64 | 24 |
| 戰區總飛機數（抽象 + 具體） | 200+ | 100+ |
| 同時進行的爭奪點 | 6–8 | 3–4 |
| AI + 模擬每幀 CPU | ≤ 3 ms | ≤ 2 ms（30–60 fps） |
| 飛行員決策頻率 | 10 Hz，交錯排程 | 5 Hz，交錯排程 |
| 地形視線查詢 | 高度場 + 地平線快取 | 較粗的高度場 |
| 指揮官規劃 | 戰爭日之間 < 1 s | 戰爭日之間 < 2 s |

**粗估依據**：一次動作評估約為 10 個動作 × 15 個特徵的純算術，在微秒到數十微秒之間；40 架飛機 × 10 Hz 下，每幀遠低於 1 ms。地形視線是最大的變數，需要依賴預計算的地平線圖與時間切片，而它將直接受益於 repo 正在規劃的地形整合層（`docs/architecture/xinyi-terrain-integration-plan.md`）。

**決定性**：固定時間步長。同平台、同版本下的決定性足以支援 Battle CI；多人模式採用伺服器權威，而不是鎖步同步，避免跨平台浮點決定性這個大坑。

### 7.3 刻意不做的事

- **執行期強化學習或神經網路飛行員**：不透明、難調、會鑽漏洞。強化學習只當離線測試員。
- **執行期大型語言模型**。
- **每架飛機都配 HTN／GOAP 規劃器**：動作 + 效用就夠了，規劃只放在指揮官層。
- **全戰區即時高精度模擬**與**即時全域 MCTS**。
- **Nemesis 式的敵人階層與晉升系統**。
- **讓玩家做 RTS 式的單位操控**：玩家是飛行員，不是將軍。他的戰略影響力來自位置選擇與聲望請求。
- **擬真航電**。

### 7.4 階段計畫與閘門（時程為量級估計，假設 4–8 人的小團隊）

| 閘門 | 內容 | 通過條件 | 不通過時的行動 |
|---|---|---|---|
| **G0 紙上戰爭**（2–4 週，1–2 人） | 用試算表或 Python 跑無頭的抽象戰爭，含指揮官 | 至少 60% 的戰爭出現 ≥ 2 次領先易手；第 3 天前分出勝負的比例 ≤ 15%；方案多樣性足夠 | 抽象戰爭本身就無聊，先修戰略模型，其他一律暫停 |
| **G1 一場好打的 4v4**（3–4 個月） | 飛行員層 + 語法 + 無線電 + 失誤模型，不含戰略層 | 盲測中玩家預測敵方下一步的準確率顯著高於機率；玩家「想再打一場」；AI 物理違規 = 0 | **4v4 本身不好玩，上層架構救不了它。** 回頭重做手感與動作 |
| **G2 三條戰線**（3–4 個月） | 爭奪點 + 校準解算 + 天氣圖 | 校準差異 < 5 pp；玩家察覺不到物化穿幫；玩家影響力 15–30 pp；「錯過精彩」的抱怨率低 | 退回半動態戰役（見 8.2 節） |

| **G4 人格與宿敵、合作原型** | | | |

## 8. 弱點與風險

### 8.1 風險表

| # | 風險 | 可能性 | 影響 | 緩解方式 | 早期警訊 |
|---|---|---|---|---|---|
| 1 | **湧現的無聊**：自主戰爭大多時候是互相消耗 | 高 | 高 | 爭奪點時鐘 + 賭注；命運取樣器；G0 戲劇指標 | G0 的領先易手次數低 |
| 2 | **玩家無力感或被帶飛**：友軍太強或太弱 | 高 | 高 | 玩家影響力目標 15–30 pp；反事實簡報 | 測試者說「我在不在都一樣」 |
| 3 | **物化穿幫**：飛機憑空出現或位置不合理 | 中 | 高 | 先出現航跡再出現機體；目視距離外生成；與空情圖一致 | 測試錄影中出現「冒出來」的時刻 |

| 5 | **導演被看穿，或被當成作弊** | 中 | 中 | 只碰未觀測的部分；偏差稽核；提供純粹模式 | 社群出現「橡皮筋」的說法 |

| 7 | **無線電過載** | 高 | 中 | 優先級佇列；頻寬預算；只播與玩家相關的內容 | 測試者關掉無線電 |
| 8 | **手機操作與效能** | 中 | 高 | 動作輔助操控；縮小模擬範圍；較短的出擊 | 中階機超出幀預算 |
| 9 | **範圍膨脹**：四層加導演的成本 | 高 | 高 | 嚴格依閘門推進；每層先做最笨的版本 | 階段 1 延期超過 50% |

| 11 | **地緣政治與平台風險**：真實城市、真實空軍的題材讓敵方設定高度敏感，可能影響區域發行與平台審核 | 中 | 高 | 採用虛構陣營或抽象紅藍（類似 Ace Combat 的 Strangereal 做法）；戰場引擎本身與陣營無關 | 發行與平台方的回饋 |

| 13 | **多人同步** | 中 | 高 | 伺服器權威；以爭奪點作為興趣管理單位；導演關閉 | |

### 8.2 最大的賭注，以及什麼證據會證明我錯了

整份提案押在一個假設上：

> **「校準過的自主戰爭 + 可讀的 AI」每小時產生的難忘故事，會比手工任務更多。**

如果 G0 與 G2 顯示大多數出擊感覺像隨機雜訊，也就是測試者無法複述有因果關係的故事，就應該退回**半動態戰役**：保留飛行員層與爭奪層（這兩層無論如何都比 Ace Combat 的僚機系統更有深度），但把戰區自主權換成手工任務模板加動態爭奪點。這仍然有差異化，只是不再是「活的戰爭」。

我對飛行員層與簡令語法有高度信心：它們的技術風險低，可讀性的效益已有前例（F.E.A.R. 透過隊員喊話讓 AI 看起來比實際更聰明）。我對校準式 LOD 有中等信心：方法本身成熟，但物化的手感需要大量打磨。我對命運取樣器的信心最低：數學上乾淨，但玩家如何感受它，必須用 A/B 測試來回答，不能用推理來回答。

## 9. 與既有專案的關係與建議的下一步

- 本研究**不改變**任何幾何、地形或 Unreal 閘門的優先順序。依照 `AGENTS.md`，玩法不應混入 Unreal 匯入閘門。
- 戰場引擎與城市管線唯一的交會點是**地形與城市作為戰術地形**：雷達遮蔽、低空突穿走廊、城市上空的防空。這應該在地形整合層穩定之後才開始對接。
- 建議的第一步是 **G0 紙上戰爭**：成本最低、資訊量最高，而且不需要任何引擎。
